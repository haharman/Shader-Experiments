# センサー位置の調整（パラメーターだけで行う）

RPLIDAR C1 の測定点を、画面（板）の UV に合わせる手順。キャリブレーション機能は作らず、`SensorInputSource` の Inspector の値を手で合わせる。
対象のコンポーネントは、シーン `CosmicInteractive.unity` の `SensorInputSource`（`RpLidarC1` と同じ GameObject）。

## 1. 座標の決まり方

[SensorInputSource.cs](../Assets/CosmicInteractive/Scripts/Sensing/SensorInputSource.cs) の `ToBoardPoints` と `ToUv` が、点をこう変換している。

```
a = (センサーの生の角度 − angleOffsetDeg) を 0〜360° に折り返したもの
x = 距離 × sin(a)        板座標[mm]。右が正
y = −距離 × cos(a)       板座標[mm]。下が正。原点はセンサーの回転中心

板の範囲 :  −boardWidthMm/2 ≤ x ≤ boardWidthMm/2,  0 ≤ y ≤ boardHeightMm
UV       :  u = 0.5 + x / boardWidthMm
            v = 1 − y / boardHeightMm        （v は上が1。画面の上端が y=0）
```

つまり実装は、次の配置を前提にしている。

```
            センサー（上辺の中央。回転中心が板の上辺の線上）
                 ●  ← 原点 (x=0, y=0) = UV (0.5, 1)
   ┌─────────────┼─────────────┐ ─ y=0   v=1
   │             │             │
   │      板（画面に映る範囲）     │
   │             ▼ y+          │
   └───────────────────────────┘ ─ y=boardHeightMm   v=0
   x=−W/2                    x=+W/2
   u=0                         u=1
```

- `a = 180°` が板の正面（センサーの真下）。`angleOffsetDeg = 180` なら、センサーの生の角度 0° が正面になる。
- 点の並びの継ぎ目（折り返しの 0°）は、板の反対側にある。板の中で塊が分かれることはない。

## 2. 使うパラメーター

| パラメーター | 役割 | 触るとき |
|---|---|---|
| `angleOffsetDeg` | センサーの回転ずれ。正面がずれているとき | 最初に合わせる |
| `boardWidthMm` | 板の幅[mm]。u の拡大率 | 左右の端が合わないとき |
| `boardHeightMm` | 板の高さ[mm]。v の拡大率。半径(`radiusMm`)の基準でもある | 上下の端が合わないとき |
| `backgroundMarginMm` | 背景より何mm近ければ「前景」とするか | 壁や板が手として拾われるとき |
| `blobGapBaseMm` / `blobGapFactor` / `minBlobPoints` / `minBlobWidthMm` | 点のまとめ方 | 指が拾われる／手が割れるとき |
| `maxMatchMm` / `graceSeconds` / `velocitySmoothing` | 追跡 | 手の動きが飛ぶ／ちらつくとき |
| `minSpeedMmPerSec` / `radiusMm` | 流体への出力 | 位置が合ったあとの見た目の調整 |

## 3. 準備

1. センサーを板の上辺の中央に置く。回転中心が上辺の線の上に来るようにする。ずれると §7 の「足りない点」にある通り、パラメーターでは直せない。
2. センサーの走査面を板の面に平行にする。板から手を浮かせたときに反応する高さが、そのまま誤差になる。
3. `SensorInputSource` の `logTouches` を ON にする（シーンでは ON）。
4. 何も触れない状態で再生し、ログの `[BackgroundModel] 背景を記録しました` を待つ。記録中に人がいたら、離れて `B` キーで取り直す。
5. 画面に、位置の目印を出しておく（板の端や、中央に十字などの画像）。

## 4. 測り方

`logTouches` が ON のとき、新しく触れるたびに次のログが出る。

```
[SensorInputSource] touch id=3 uv=(0.27, 0.77)
```

- 同じ場所で測り直すときは、手を離して `graceSeconds`（0.3秒）以上待つ。待たないと同じ ID のままで、ログが出ない。
- 1秒ごとに `points= foreground= inBoard= blobs= tracks=` も出る。
  - `foreground` が増えて `inBoard` が 0 のまま：板の範囲の外にいる。`angleOffsetDeg` と板のサイズを疑う。
  - `inBoard` は増えるが `blobs` が 0：`minBlobWidthMm` が大きすぎる、または点が少ない。
- 測るときは、毎回同じ触り方をする（手のひらを立てる、など）。点は手のセンサー側の面にしか当たらないので、手の厚みぶん、中心が実際よりセンサー寄りになる。

測った UV を `(u, v)`、そこに触れたときに期待する UV を `(u*, v*)` とする。

## 5. 調整の順番

必ず「回転 → 幅 → 高さ」の順に行う。回転がずれたまま幅を合わせても、合わない。

### 5-1. 回転（`angleOffsetDeg`）

1. 板の左右の中央（`u* = 0.5`）で、できるだけセンサーから遠い位置（下端の近く）に触れる。
2. ログの `(u, v)` から、ずれの角度を出す。

   ```
   x = (u − 0.5) × boardWidthMm
   y = (1 − v)   × boardHeightMm
   新しい angleOffsetDeg = 今の angleOffsetDeg − atan2(x, y)[度]
   ```

   `x > 0`（右にずれて見える）なら、`angleOffsetDeg` を減らす。
3. 値を入れ直して、同じ場所をもう一度測る。`u` が 0.5 になるまで繰り返す。
4. 遠い位置で `u` が合ったら、近い位置（上端の近く）でも確かめる。近くでずれるなら、センサーが上辺の中央にない（§7）。

### 5-2. 幅（`boardWidthMm`）

1. 左端と右端に近い位置（`u* = 0.1`、`u* = 0.9` など）に、それぞれ触れる。
2. 次の式で幅を直す。中央からの距離が大きいほうの点を使うと、誤差が小さい。

   ```
   新しい boardWidthMm = 今の boardWidthMm × (u − 0.5) / (u* − 0.5)
   ```

   例：`u* = 0.9` の位置で `u = 0.8` と出たら、`× 0.3/0.4 = 0.75`。幅を小さくする。
3. 板の実寸が分かっているなら、その値から始める。画面の縦横比（`resolution` は 2560×800 で 3.2）と、`boardWidthMm / boardHeightMm` も一致しているはず。

### 5-3. 高さ（`boardHeightMm`）

1. 板の下端に近い位置（`v* = 0.1` など）に触れる。
2. 次の式で直す。

   ```
   新しい boardHeightMm = 今の boardHeightMm × (1 − v) / (1 − v*)
   ```

   `boardHeightMm` を変えると `radiusMm` の UV での大きさも変わる。最後に `radiusMm` を見直す。

### 5-4. 確認

- 四隅と中央の5点に触れて、`(u, v)` が目印の位置と 0.03 ほど以内で合っているか見る。センサーの測定の細かさは、距離が 2m で 1点あたり約 25mm なので、これ以下の精度は出ない。
- 手を動かしたとき、魚や流体が手の位置から反応しているか、画面で確かめる。
- 合わなければ、5-1 に戻る。

## 6. Play 中に変えた値の扱い

Unity は、Play を止めると Inspector の値を元に戻す。

1. Play 中に合わせた値を、メモする（`angleOffsetDeg`、`boardWidthMm`、`boardHeightMm`）。
2. または、`SensorInputSource` の右上のメニューから `Copy Component` し、Play を止めてから `Paste Component Values` する。
3. シーンを保存する。値は `CosmicInteractive.unity` に残るので、コミットするか、控えを取る。

## 7. 実装で足りない点

「パラメーターだけで調整する」ときに、合わせられない・合わせにくい点。

### パラメーターで直せない（配置を守る必要がある）

1. **板の原点のオフセットがない。** `ToUv` は `u = 0.5 + x/W`、`v = 1 − y/H` に固定されている。センサーが上辺の中央にないと、位置がずれる。`boardOffsetMm`（x, y）のような値が要る。
2. **左右・上下の反転がない。** 今回は `angleOffsetDeg = 180` で足りたが、センサーを裏返す、映像を反転して出す、といった場合は、角度の符号を変えるパラメーターが要る。
3. **板を傾けた配置に対応していない。** 板の座標は、センサーの座標と平行（回転だけ）の前提。台形のゆがみ（映像の斜め投影）は直せない。
4. **手の厚みの補正がない。** 塊の中心は、手のセンサー側の面の平均なので、実際の手の中心よりセンサー寄りに出る。センサーから遠いほど、ずれが目立つ。

### 確認する手段が足りない

5. **触れている位置を画面に重ねて描く機能がない。** `VelocityInputDebugView` は、速度が `minSpeedMmPerSec` 以上の入力だけを描く。止まっている手は出ない。シーンでは無効（`m_Enabled: 0`）。
6. **板の範囲と生の点群を描く機能がない。** `inBoard=0` のとき、点がどこにあるのかが分からない（今回の原因調査でも、ログからは分からなかった）。範囲外にされた点の x, y も出ていない。
7. **ログの精度が粗い。** `uv=(0.27, 0.77)` は小数2桁で、新しく触れたときに1回しか出ない。板座標[mm]も出ない。5-1 の式の精度が、ここで決まってしまう。
8. **画面と板の縦横比の確認がない。** `resolution`（2560×800）と、`boardWidthMm / boardHeightMm`（2000/800）が食い違っていても、警告は出ない。

### 運用で困りやすい点

9. **板の範囲が、そのまま触れる範囲になっている。** 端に触れた手は、中心が範囲の外に出ると捨てられる。範囲に余白を持たせる値がない。
10. **背景の取り直しが `B` キーだけ。** 起動時に人が板の前にいると、背景に混ざる。自動で取り直す、画面のボタンから取り直す、といった手段がない。
11. **センサーの再接続がない。** `RpLidarC1` は、`Failed` になると戻らない（COM ポートが無いときなど）。ケーブルを抜き差ししたら、アプリを再起動する必要がある。
12. **`Calibration.cs` が書きかけ。** `// 実装中` のまま、メソッドが空で、シーンにも付いていない。この方針なら、削除するか、別のブランチに移す。
